### Defect A — `AGENTS.md` states a falsehood about Codex

Current text, lines 29-33:

> "Codex has no equivalent of Claude Code's hooks, skills, or `Skill`/`Agent` tooling. It cannot run
> `code-review`, `security-review`, `verify`, `ship`, or `migration-safety`, and it does not get the
> git-guardrails PreToolUse hook."

The second sentence is **true and must survive**. The first is **half false**: Codex gained SKILL.md
support in Dec 2025 — `.codex/skills/` at project scope, `~/.codex/skills/` personal, with an **8 KB
skill-body cap**. Hooks and the `Skill`/`Agent` tooling remain genuinely unportable.

Rewrite to state precisely what Codex does and does not have. Do not overcorrect into implying the
pipeline runs there — that would reproduce T085's "looks live and is not" defect in the other
direction.

### Defect B — no projection mechanism exists

`install_abs` (`setup.sh:154`) does symlink-or-copy, but its header comment forbids reuse:
*"do not repurpose for the base install, which always copies via `harness_copy_manifest`."* It is
used only by `install_pack`. **The base install has no projection step — this is new code, not a
reuse.** (An earlier Supervisor claim that the mechanism already existed was wrong; it is corrected
here so the implementer does not go looking for it.)

### What ships

- `MANIFEST` gains a **destination map**: which canonical path lands in which directory per harness.
  Keep the existing one-path-per-line format working unchanged for the Claude default; a project that
  never passes `--harness` must behave exactly as it does today.
- `setup.sh --harness <name>` (repeatable) and the same flag on `update.sh`. Default with no flag:

- Generated vendor directories are **gitignored** downstream. Canon is committed; projections are not.
- `AGENTS.md` corrected per Defect A, with an accurate Codex limits section.
- A Codex-specific limits statement naming what cannot run there: hooks, `code-review`,
  `security-review`, `verify`, `ship`, `migration-safety`.

### The 8 KB rule (load-bearing, from `DDR-0007`)

Codex caps a skill body at 8 KB. Several skills in this repo exceed that.

**On an oversize skill, fail loudly. Never truncate.** A silently trimmed skill looks installed and
behaves worse, which is strictly worse than "skill not found" because it is invisible. The install
must name the offending skill and its size, and either abort or skip-with-a-loud-warning — that
choice is the implementer's, but silence is not an option. This is the single rule carried forward
from the deferred Option C.

**Out of scope**:
- Cursor, Gemini, OpenCode, Copilot, Antigravity. N=2 was chosen deliberately: `DDR-0006`'s follow-up
  says *"at N=4 the generator's cost/benefit inverts and this DDR should be reconsidered rather than
  assumed."* Adding a third or fourth harness here would silently cross that line. Cursor keeps its
  existing `DDR-0006` doctrine-only stub.
- Content transformation per harness (`tools/adapters/`, Option C) — deferred until a real format
  divergence is measured. The 8 KB rule above is the one exception, and it is a *check*, not a
  transformation.
- Relocating `.claude/hooks/` or `.claude/settings.json`.
- `packs/` and `install_pack()`.
- Any change to `DDR-0006`'s adapter architecture. One factual sentence in `AGENTS.md` changes; the
  design does not.

## Approach

**Vital slice**: `--harness codex` producing a working `.codex/skills/`, plus the `AGENTS.md`
correction. Those two together are what turns the user's reported symptom from true to false.

**Cut list**:
- No Cursor, Gemini, or other harness. N=2 by decision.
- No content transformation per harness. The 8 KB check is a check, not a transform.
- No `npx`-style installer or marketplace manifest, however common in the repos scanned.
- No migration tooling for `packs/`.

**Recommended approach.** Extend `MANIFEST` with an optional destination column rather than inventing
a second config file — the format is already "one resource path per line" with `#` comments, and a
trailing map keeps a single source of truth for what gets deployed where. Default destination stays
the current one, so AC1 is satisfied by construction rather than by care.

Write the projection as new code in `lib/harness-fetch.sh` alongside `harness_copy_manifest`, not by
repurposing `install_abs` — its header comment forbids that, and `ADR-0001` deliberately moved the
base install off the symlink model.

Do the `AGENTS.md` correction **first**, in its own commit. It is a three-line edit that independently
closes half of the user's reported problem, and it is the piece most likely to be lost if the install
work runs long.

**On AC3, which is the one that actually matters.** Every other criterion can pass while a Codex
session still fails to find a skill — file layout is a proxy, not the goal. Do not substitute a
directory listing for a transcript. If Codex is not available in the environment, report AC3 as
**BLOCKED with the reason**, and do not mark the task Done: `DDR-0007`'s follow-up names this
explicitly — *"B2 must verify a real Codex session finds a skill by name, not merely that files
landed."*
